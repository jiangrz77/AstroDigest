# AstroPaperDigest v2.2.2

## Critical macOS startup fix

- Include the `latex2mathml` symbol data in both the desktop app and its embedded
  CLI. The v2.2.0 release omitted `unimathsymbols.txt`, causing startup to fail
  before the window appeared and also preventing the background pipeline from
  starting.
- Apply the fix to both the DMG release builder and the local app builder.
- Gate packaging on signed-bundle integrity, required resources, real GUI/CLI
  startup, and local-page/offline-asset checks. Smoke tests use a temporary
  `APD_DATA_DIR`; they do not fetch papers or send email and do not use existing
  user settings, digests, or the running app's single-instance lock.
- Run offline regression tests before publishing releases.

This release also includes the previously local v2.2.1 email and update workflow
fixes, including mandatory update checksums and safer email settings handling.

## Installation

Download `AstroPaperDigest-2.2.2.dmg` and copy the app to Applications, replacing
the old application after quitting it. Existing user data remains in
`~/Library/Application Support/AstroPaperDigest` and is not replaced by the app
bundle. A broken v2.2.0 app may require this manual installation because its
in-app updater cannot be reached.

This is an Apple Silicon (arm64) build. It retains the existing ad-hoc signing
policy, not Developer ID signing/notarization, so macOS first-launch security
confirmation may still be required. The missing-resource fix does not remove
that separate security prompt.

## Release verification

The builders automatically run `verify_bundle.py` before producing distributable
artifacts. A desktop-session check can also be run explicitly:

```sh
python3 verify_bundle.py /path/to/AstroPaperDigest.app --window
```

The checker launches only its own isolated test instance and closes it after
verification. Release asset SHA-256 checksums are appended by the release workflow.
